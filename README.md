# extera

an experimental overlay that adds a second, python plugin engine from [exteraGram](https://github.com/exteraSquad/exteraGram) to entinyGram.

[website](https://entaytion.is-a.dev/entinygram) · [channel](https://t.me/entinyGram) · [donate](https://entaytion.is-a.dev/donate)

> **experimental.** this is not part of official entinyGram releases. expect crashes and plugins that do not install or run. the [acceptance checklist](docs/acceptance.md) has not been passed on a device.

## what is inside

| path | contents |
| --- | --- |
| `apply.ts` | applies and reverts the overlay: `--check`, `--status`, `--revert`, `--map` |
| `build.ts` | numbered local build, `YYYYMMDDNN` |
| `sdk.ts` | packs and signs the python sdk |
| `manifest/` | what goes where |
| `overlay/` | our screens, bridge, strings and the engine gradle script |
| `tests/` | `bun test` and `verify.ts` |
| `docs/` | documentation, in ukrainian |

the overlay commits nothing into entinyGram and does not touch the patch stack. it writes into `src/` and `worktree/` as uncommitted changes, and `build.ts` removes them after the build.

## quick start

needs a prepared [entinyGram checkout](https://github.com/entinyGram/android#quick-start), bun, java and python 3.11. clone into `extera-plugins/` at its root:

```sh
git clone https://github.com/entinyGram/extera.git extera-plugins
```

build numbers live in `extera-plugins/var/config.yaml`. create it once:

```yaml
build version: "2026010100"
```

then run from the entinyGram root:

| action | command |
| --- | --- |
| check without changing anything | `bun extera-plugins/apply.ts --check` |
| apply | `bun extera-plugins/apply.ts` |
| revert | `bun extera-plugins/apply.ts --revert` |
| build an apk (apply, build, revert) | `bun extera-plugins/build.ts` |
| preview the build | `bun extera-plugins/build.ts --dry-run` |
| test | `bun test extera-plugins/tests` |

in-app updates stay off unless `extera-plugins/var/update-invite` holds the invite hash of an update channel.
