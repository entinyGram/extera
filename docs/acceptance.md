# acceptance

накладка вважається прийнятою, лише коли кожен пункт пройдено на реальному пристрої з apk, зібраним `build.ts` на чистій базі. у звіті вказуй номер apk, пристрій і версію android.

## пакет

- [ ] `bun extera-plugins/apply.ts --check` зелений на чистому checkout
- [ ] `bun test extera-plugins/tests` зелений
- [ ] `apply.ts`, потім `apply.ts --revert`, і `git status` entinyGram без змін від накладки
- [ ] у `overlay/` немає symlink, `docs/hooks.md` збігається з `apply.ts --map`

## пристрій

- [ ] cold start без крашу з вимкненим і з увімкненим рушієм
- [ ] увімкнення і вимкнення рушія в поточному процесі, повторне відкриття налаштувань
- [ ] валідний `.plugin` встановлюється з нашого picker
- [ ] валідний `.plugin` встановлюється з документа в чаті, і завантаженого, і ще не завантаженого
- [ ] `.py` встановлюється, `.elyx`/`.eaf` перевірено на відомо сумісному прикладі
- [ ] enable, disable, reload і uninstall зберігають стан після перезапуску
- [ ] налаштування і дозволи плагіна не втрачають значення і не падають
- [ ] реальний python hook або пункт меню виконується
- [ ] quickjs-плагін встановлюється і працює і з вимкненим, і з увімкненим python
- [ ] екрани відповідають нашому inu ui у світлій і темній темі та при перемиканні теми наживо
- [ ] плагін користувача працює, або є точна причина першої несумісності з логом
